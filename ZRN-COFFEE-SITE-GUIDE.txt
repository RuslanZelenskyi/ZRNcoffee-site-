----------------------------------
Ты помогаешь развивать сайт интернет-магазина свежеобжаренного кофе
ZRN Coffee. Прочитай приложенный файл ZRN-COFFEE-SITE-GUIDE.txt — это
актуальное описание архитектуры. Правила работы:
 • Владелец не программист. Объясняй по-русски, по шагам, что нажать и куда
   вставить. Отдавай ЦЕЛЫЕ готовые файлы, а не куски «вставь сюда».

 • Перед выдачей файла проверяй: синтаксис JS (node --check), сборку
   (python tools/build.py), браузерный прогон (Playwright), Apps Script на моке.
 • Секреты (токены, ключи) НИКОГДА не вписывай в файлы сайта — только в
   Script Properties Apps Script (см. раздел 7).
 • Сначала смотри раздел «Известные подводные камни» (раздел 13).
 • Источник правды по данным: catalog.json (тексты, фото, сорта) +
   Google Таблица (цены, веса, порядок, показывать/скрыть, порог доставки,
   «от … ₴» в шапке, опубликованные отзывы).
Если файлов не хватает — спроси у владельца, не придумывай.

0. КРАТКО: ЧТО ЭТО ЗА САЙТ
----------------------------------------------------------------------
• Статический сайт на GitHub Pages (нет своего сервера и базы данных).
• Одностраничный магазин (index.html: каталог, карточки-модалки, корзина,
  оформление заказа, FAQ, блог, отзывы) + набор сгенерированных
  страниц (по каждому сорту, статьи блога, статус заказа, форма отзыва,
  короткие ссылки для соцсетей, 404).
• Два языка: украинский (корень /) и русский (/ru/...).
• Заказы НЕ оплачиваются на сайте. Оформление = заявка: Web3Forms (письмо
  владельцу) + Google Apps Script (запись в Google Таблицу, Telegram-бот,
  письмо покупателю). Оплата — переводом на карту или наложенным платежом;
  доставка — Нова Пошта / Укрпошта.
• «Мозг» бэкенда — Google Apps Script, привязанный к Google Таблице.
• Сборка: Python-скрипт tools/build.py запускается в GitHub Actions при
  каждом деплое (и раз в час), берёт данные из catalog.json и Google
  Таблицы и генерирует страницы.

2. ОБЩАЯ АРХИТЕКТУРА (схема потоков)
----------------------------------------------------------------------

 ┌────────────────────── GitHub (репозиторий) ──────────────────────┐
 │ catalog.json + index.html + tools/build.py + analytics.js + ... │
 └───────────────┬──────────────────────────────────────────────────┘
                 │ push в main / кнопка «Оновити сайт» / раз в час (cron)
                 ▼
 GitHub Actions "Build and Deploy Site":
   1) python tools/build.py
        ├─ читает catalog.json
        ├─ делает HTTP GET в Apps Script  ?prices=1 → получает из Google
        │   Таблицы цены, веса, порядок, видимость, настройки, отзывы
        ├─ вставляет данные в index.html (между маркерами)
        └─ генерирует страницы (сорта, блог, ru/, status, review, 404…)
   2) публикация всей папки на GitHub Pages → https://zrncoffee.com.ua/

 Посетитель (браузер) ──► статический сайт (index.html + страницы)
     │  оформляет заказ:
     ├─► Web3Forms API ──► письмо владельцу (zrncoffee@gmail.com)
     └─► Google Apps Script (web app) ──► Google Таблица, лист «Замовлення»
                                          ├─► Telegram-бот (уведомление)
                                          ├─► письмо-подтверждение покупателю
                                          └─► (позже) Нова Пошта API → статус
     Страница /status/ ──► Apps Script (kind:'status') ──► данные заказа
     Форма /review/    ──► Apps Script (kind:'review') ──► лист «Відгуки»
     Выбор города/отделения НП ──► Apps Script (?np=...) ──► Нова Пошта API

 Аналитика: analytics.js ──► Google Analytics 4, Meta Pixel, Microsoft
 Clarity (последние два — только после согласия на cookie).

Важная идея: сайт статический, поэтому ЛЮБОЕ изменение цен/отзывов из
Таблицы попадает на сайт только после ПЕРЕСБОРКИ (кнопка «Оновити сайт»
в меню таблицы, либо автоматически раз в час). Между пересборками сайт
показывает прошлые данные.

3. ГЛАВНЫЙ ФАЙЛ index.html
----------------------------------------------------------------------
3.1 Устройство
  • Один файл: <style> (CSS), разметка, <script> (вся логика).
  • Перевод: объект ZRN_I18N = {uk:{...}, ru:{...}}; функция t(ключ)
    возвращает строку нужного языка и подставляет токены {free},
    {heroW}, {heroP} (см. 4.3). Статический HTML с атрибутами data-i18n /
    data-i18n-html переводится при загрузке (applyStaticI18n).
  • Язык хранится в localStorage zrn_language; русские версии сгенерированных
    страниц лежат в /ru/..., русская главная — отдельный адрес /ru/
    (это тот же index.html: сборка делает копию ru/index.html с русскими
    title/description/canonical; язык выбирает JS по адресу, см.
    initLanguage/setLanguage; старые ссылки /?lang=ru перенаправляются).
  • Каталог в JS: ALL_PRODUCTS = [...PRODUCTS (mono), ...BLENDS (blend)]
    (блок данных сгенерирован сборкой).
  • Корзина: объект cart в localStorage ключ zrn_cart_v2; ключ позиции
    "id|помол|вес". sanitizeCart() выкидывает позиции, у которых сорт
    удалён/скрыт или вес больше не существует (если вы поменяли веса).
  • Модалка сорта: openProduct(id). У каждого сорта ДВА веса p.w1 и p.w2
    и цены p.price1 / p.price2 (из Таблицы). Цена за 100 г и выгода
    считаются на лету: выгода = price1*w2/w1 − price2.
  • Оформление заказа: форма в корзине. Перед отправкой запрашивается номер
    заказа у Apps Script (getOrderNumber(), ?n=new). Если Apps Script
    недоступен — запасной номер вида ZRN-ГГММДД-R###.
  • Отправка заказа: параллельно в Web3Forms и в Apps Script
    (достаточно, чтобы сработал любой). После успеха — экран подтверждения
    с номером заказа и ссылкой на статус.
  • Блок отзывов: массив REVIEWS (генерируется сборкой из Таблицы).
  • Автообновление: если сайт был в фоне 10+ минут и не открыты окна/форма,
    страница сама перезагружается (чтобы не показывать старые цены).

3.2 Константы в index.html (ищите по имени)
  WEB3FORMS_KEY      публичный ключ Web3Forms (не секрет, привязан к email).
  ORDER_SHEET_URL    адрес web app Apps Script (…/exec). ЭТО ЖЕ место,
                     откуда build.py берёт адрес для чтения цен.
  TG_CONTACT         ссылка на Telegram-контакт для покупателей.
  SITE               https://zrncoffee.com.ua/
  ZRN_SET            {freeShip, heroW, heroP} — генерируется (3.3).
  FREE_SHIP_FROM     = ZRN_SET.freeShip (порог бесплатной доставки).
  Если Apps Script пересоздают заново — адрес /exec меняется, и его надо
  заменить в ORDER_SHEET_URL (раздел 7.5).

3.3 Маркеры, которые ПЕРЕЗАПИСЫВАЕТ build.py (руками внутри не править!)
  /*CATALOG:START … CATALOG:END*/        данные сортов и статей (JS)
  <!--CAT:NOSCRIPT:START … END-->         список сортов для браузеров без JS
  /*SETTINGS:START … SETTINGS:END*/       ZRN_SET (порог доставки, шапка)
  /*REVIEWS:START … REVIEWS:END*/         опубликованные отзывы
  <span data-v="freeShip|heroW|heroP">…</span>   числа в статичном HTML
  Всё, что ВНЕ маркеров, сборка не трогает.

4. ДАННЫЕ: catalog.json И GOOGLE ТАБЛИЦА — КТО ЗА ЧТО ОТВЕЧАЕТ
----------------------------------------------------------------------
4.1 catalog.json (правится на GitHub: файл → карандаш → Commit)
  Разделы: _help, site, products, posts, brewGuide, processInfo.
  site: {url, telegram, email}; необязательно "pricesFromSheet": false —
        отключить чтение цен из Таблицы (брать из catalog.json).
  products[] (один блок {…} = один сорт), обязательные поля:
    id           латиницей маленькими, цифры, дефис (используется в URL и
                 в Таблице!)
    type         "mono" или "blend"
    name, img (путь в img/), alt, accent (цвет #hex)
    price200, price500   ЗАПАСНЫЕ цены (целые числа без кавычек) — нужны,
                 пока сорта нет в листе «Ціни» или Таблица недоступна офлайн
    region, variety, roastLabel, notes, info, story   — тексты {uk, ru}
                 (story — список абзацев)
    processing   washed / natural / ... (ключ из processInfo)
    roastLevel   1..5
    taste        {acid, sweet, bitter, body} каждое 1..5
    brew         список способов (должны существовать в brewGuide)
    необязательно: badge/badgeType (метка «Новинка»/«Популярне»), ratio
  posts[]: {id, k (категория), title, excerpt, body} — каждое {uk, ru};
           абзацы в body разделяются \n\n.
  build.py проверяет файл и при ошибке останавливает сборку с понятным
  сообщением (в Actions — красный крестик; сайт остаётся прежним).

4.2 Google Таблица «ZRNcoffee Orders» (привязана к Apps Script)
  Лист «Замовлення»  — все заказы (колонки в разделе 6.1).
  Лист «Ціни»        — управление сортами (создаётся функцией setupPrices):
     A  ID (не менять)  — должен СОВПАДАТЬ с id в catalog.json
     B  Сорт            — название (для вашего удобства)
     C  Показувати      — Так / Ні (Ні = сорт и его страница пропадают)
     D  Порядок         — число; сортировка внутри блока «моносорта»
                          и внутри «бленды» отдельно
     E  Вага 1, г       F  Ціна 1, ₴
     G  Вага 2, г       H  Ціна 2, ₴
     I,J,K  формулы: ₴ за 100 г (вес 1), ₴ за 100 г (вес 2), выгода при
            весе 2. Это ТОЛЬКО для вашего удобства, сайт считает сам.
     Жёлтые клетки — редактируемые; серые/зелёные — служебные.
     Если в Таблице НЕТ строки сорта — берутся цены из catalog.json.
     Если вес 1 > вес 2 — сборка сама поменяет их местами.
  Лист «Налаштування» — B2: «Безкоштовна доставка від», B3: вес в шапке
     (напр. 200), B4: цена в шапке «від …» (напр. 260). B3/B4 пустые =
     авто (самый частый вес 1; минимальная цена на этом весе).
  Лист «Відгуки»     — отзывы с формы (колонки: Дата, Ім'я, Оцінка, Сорт,
     Відгук, № замовлення, Перевірена покупка, Мова, Статус). Статус:
     Новий / Опубліковано / Відхилено. На сайт попадают «Опубліковано»
     (новые первыми, максимум 12).
  Меню «☕ ZRN сайт» в Таблице: Оновити сайт; Перевірити ціни; Налаштувати
  GitHub (один раз); Створити листи «Ціни» і «Налаштування».

4.3 Токены подстановки в текстах
  В словарях переводов и catalog используются {free}, {heroW}, {heroP}.
  t() и ui_texts() (build.py) заменяют их на значения из «Налаштування».
  Место в HTML без JS: <span data-v="freeShip">1400</span> (сборка
  подставляет актуальное число).

4.4 Что происходит, когда вы меняете данные
  • Цена/вес/порядок/порог → правите Таблицу → «Оновити сайт» → через 1-2
    минуты сайт обновлён (иначе — не позже чем через час).
  • Спрятать сорт → «Показувати = Ні» → «Оновити сайт». Страница сорта
    удаляется сборкой.
  • Новый сорт → см. раздел 11.2 (нужна ПОЛНАЯ карточка в catalog.json).
  • Текст/фото/вкус сорта, статьи блога → catalog.json на GitHub.

5. СБОРЩИК tools/build.py (по шагам main())
----------------------------------------------------------------------
Запуск: python tools/build.py (из корня репозитория). Переменные окружения
для тестов: ZRN_OFFLINE=1 — не читать Таблицу (цены из catalog.json);
ZRN_SHEET_URL=<url> — другой адрес Apps Script.

Порядок:
  1. load()            читает и проверяет catalog.json.
  2. apply_sheet(cat)  GET <ORDER_SHEET_URL>?prices=1 (3 попытки). Если
                       Таблица недоступна — СБОРКА ПАДАЕТ (exit 1) с
                       понятным сообщением; опубликованный сайт остаётся
                       прежним (сделано намеренно, чтобы не показывать
                       устаревшие цены). Накладывает цены/веса/порядок/
                       видимость, считает SETTINGS, готовит REVIEWS_DATA.
                       Если ответ без поля "reviews" (старый скрипт) —
                       блок отзывов не трогает.
  3. build_index()     вставляет данные в index.html по маркерам (3.3).
  4. Site(...)         генерирует: product_pages (coffee/<id>/ uk+ru),
                       blog_pages, review_pages, status_pages, page_404,
                       short_links, sitemap.xml, pages.css.
  5. удаляет страницы сортов/статей, которых нет в каталоге, и пишет файлы.
Внутри: UI = словари интерфейса для сгенерированных страниц (uk/ru), CSS,
шаблоны REVIEW_HTML / STATUS_HTML / PAGE_404 / SHORT_HTML, словарь SHORT
(ig→instagram, tg→telegram, viber, qr, fb→facebook, tt→tiktok, yt→youtube,
x→x (twitter)) — короткие ссылки вида zrncoffee.com.ua/ig. Каждая такая
страница записывает источник визита в localStorage и перенаправляет на
главную (параметр ?to=/путь — на другую страницу).
SEO на сгенерированных страницах: <title>, description, canonical,
hreflang uk/ru, Open Graph, JSON-LD (Product с двумя Offer, Brand,
BreadcrumbList, Article для блога, Organization, ItemList каталога и
FAQPage на главной), sitemap.xml.

6. GOOGLE APPS SCRIPT (order-sheet.gs) — БЭКЕНД
----------------------------------------------------------------------
Где живёт: Таблица → Расширения → Apps Script. Это web app (Deploy →
Manage deployments): «Execute as: Me», «Access: Anyone». Адрес …/exec
вставлен в index.html (ORDER_SHEET_URL).
ВАЖНО: после ЛЮБОЙ правки кода нужно Deploy → Manage deployments →
карандаш → Version: New version → Deploy. Иначе сайт продолжит работать
со старой версией кода (меню Таблицы, наоборот, использует последний
сохранённый код сразу).

  7 Доставка | 8 Місто | 9 Відділення | 10 Оплата | 11 Товари | 12 Сума |
  13 Коментар | 14 Джерело | 15 Сторінка входу |
  16 Статус | 17 Статус оплати | 18 ТТН / трек-номер | 19 Примітка для
  клієнта | 20 Email | 21 Мова
  Статус (колонка P) и Статус оплати (Q) — выпадающие списки с цветами.
  Статусы: Прийнято, Обсмажуємо, Пакуємо, Відправлено, Отримано, Скасовано,
  Повернення (константа STATUSES в начале файла).
  Статус оплати: Накладений платіж, Очікує оплату, Оплачено, Гроші від НП
  отримано, Не забрав (відмова), Повернення коштів (PAY_STATUSES).
  Колонку «Примітка для клієнта» видит клиент на странице статуса.

6.2 Точки входа
  doGet(e):   ?np=...          прокси к API Новой Почты (города/отделения)
              ?n=new           выдать следующий номер заказа
              ?prices=1        JSON: {ok, products[], settings{}, reviews[]}
              (иначе)          текст "OK"
  doPost(e):  kind:'status'    данные заказа для страницы статуса (по
                               номеру + последние 4 цифры телефона)
              kind:'review'    новый отзыв → лист «Відгуки»
              kind:'subscribe' заявка в Клуб → лист «Підписки» (раздел 14а)
              kind:'sub_status'/'sub_action'  страница «Моя підписка»
              (иначе)          новый заказ: запись строки, Telegram,
                               письмо вам, письмо-подтверждение покупателю
  Нумерация заказов: ZRN-ГГММДД-NNN (дата + порядковый номер за день;
  счётчик в Script Properties ORDER_SEQ + проверка по таблице, под
  LockService, чтобы два заказа не получили одинаковый номер).

6.3 Прочие функции
  onEdit(e)            ввели ТТН (колонка 18) → статус «Відправлено».
  syncNpStatuses()     раз в час (триггер, создаётся installTriggers):
                       запрашивает у Новой Почты статус посылок по ТТН и
                       обновляет «Статус».
  installTriggers()    запустить ОДИН раз — ставит почасовой триггер.
  setupSheet()         оформление листа заказов (списки, цвета, ширины).
  setupPrices()        создаёт листы «Ціни», «Налаштування» (PRICE_SEED —
                       начальные значения).
  onOpen()             меню «☕ ZRN сайт».
  publishSite()        меню «Оновити сайт»: проверяет данные, затем
                       POST на GitHub API …/actions/workflows/<файл>/
                       dispatches (ref=main).
  setupGithub()        сохраняет GH_REPO, GH_WORKFLOW, GH_TOKEN.
  validatePrices_()    проверки таблицы цен (пустые, одинаковые веса,
                       большая пачка не дешевле за 100 г, все скрыты…).
  getPricesData_(), getPublishedReviews_()  данные для сборки.
  testNotify()         тест уведомлений.
  Формулы в «Ціни» (колонки I–K): скрипт их НЕ перезаписывает, а для новых
  строк копирует с готовой строки (copyTo). Разделитель аргументов формул
  зависит от языка Таблицы (укр./рус.: «;»).

6.4 Что запрашивает разрешения (OAuth) — Таблицы, внешние запросы
  (Telegram, Нова Пошта, GitHub), отправка почты (MailApp). При первом

7.6 Письма клиентам и спам (RESEND_KEY, MAIL_FROM)
  По умолчанию письма клиентам (подтверждение заказа, письма подписки) уходят
  через MailApp — с вашего Gmail под именем «ZRN Coffee». Такие письма часто
  попадают в спам (имя бренда на бесплатной почте, новая ссылка на домен).
  Правильное решение — отправка с адреса на вашем домене через Resend
  (resend.com, бесплатно 3000 писем/мес): функция sendMail_ в order-sheet.gs.
  Включается двумя Script Properties: RESEND_KEY (API-ключ) и MAIL_FROM
  (например orders@zrncoffee.com.ua). Если свойств нет или Resend не ответил —
  автоматически работает MailApp. Проверка: меню «✉️ Тестовий лист мені».
  Для домена в DNS нужны записи SPF и DKIM (их выдаёт Resend) и желательно
  DMARC: TXT _dmarc → v=DMARC1; p=none; rua=mailto:zrncoffee@gmail.com
  Заявка в Клуб дублируется вам на почту через Web3Forms (как и заказы) +
  Telegram + лист «Підписки».

7.7 Установка сайта как приложения (PWA)
  Файлы: site.webmanifest (название, иконки, ярлыки «Моя підписка» и «Статус»),
  sw.js (service worker), offline.html (страница «нет интернета»). Цены и
  каталог service worker НЕ кеширует — страницы всегда из сети, поэтому
  обновления сайта доходят сразу. Если когда-нибудь нужно сбросить кеш —
  измените VERSION в sw.js ('zrn-v1' → 'zrn-v2').
  Когда появляется плашка внизу (только на телефоне, не в режиме приложения):
   • после заказа или заявки на подписку (через ~6 с, с текстом под ситуацию);
   • со 2-го визита (через ~12 с);
   • на 1-м визите плашки НЕТ;
   • «Не зараз» — молчим 30 дней; установил — больше не показываем;
   • не показывается, пока открыт cookie-баннер.
  Всегда доступны ненавязчивые ссылки «Встановити застосунок ZRN»: в подвале и
  в окнах подтверждения заказа/подписки (видны, только если браузер умеет).
  Android Chrome — настоящее окно установки; iPhone Safari — подсказка
  «Поділитися → На екран Додому» (iOS не умеет иначе). Другие браузеры молчат.
  Тексты — в ZRN_I18N, ключи pwa.*.

7.8 Скорость (PageSpeed)
  Шрифты Google подключены без блокировки отрисовки (preload + onload) — это
  убирает основную причину медленного первого экрана на мобильном. Проверка:
  pagespeed.web.dev → адрес сайта → «Мобильные». Ориентир: Производительность 85+,
  LCP до ~2.5–3 с (тест Google идёт на медленной сети 4G, цифры строже реальных).
  Доступность (Lighthouse): переключатель языка использует aria-current (не aria-pressed);
  карточка сорта — одна ссылка, растянутая на всю карточку (без вложенных кнопок);
  заголовки идут по порядку (h2 → h3).
  Заголовками кеша GitHub Pages управлять не даёт (10 минут). Если захотите
  ускорить дальше — бесплатный Cloudflare перед сайтом (кеш, сжатие, HTTP/3).

7.9 Наборы знакомства (лист «Набори») и вид каталога
  НАБОРЫ. Лист «Набори» (создаётся меню «📋 Створити листи …», если его ещё нет).
  Один ряд = один набор. Колонки (жёлтые — ваши):
   • Показувати — Так / Ні (скрыть набор без удаления).
   • Порядок — число, как на листе «Ціни».
   • Назва (UA), Назва (RU), Опис (UA/RU), Позначка (UA/RU) — тексты; «Позначка» — ярлычок на
     карточке («Хіт», «Для знайомства»), пусто = без ярлычка.
   • Склад — ID сортов из листа «Ціни» через запятую. Вес можно писать после двоеточия:
     ethiopia:100, colombia:100, costarica:50. Без веса берётся «Вага за замовч., г».
   • Ціна набору, ₴ — фиксированная цена набора, ставите вы.
  Сайт сам считает «окремо ≈ N ₴» (цена этих сортов поштучно по цене «Вага 1») и
  показывает зачёркнутую сумму, только если набор дешевле. Клиент выбирает помол и количество;
  в заказе строка вида: «Название [набір: Ethiopia Sidamo 100 г + …] — Зернова, 1 шт — 400 ₴»
  (по составу вы сразу видите, что обжаривать).
  Раздел «Набори знайомства» на сайте появляется, только если есть хотя бы один показанный набор.
  Набор не показывается (и в логе сборки есть предупреждение), если сорт из состава скрыт в
  «Ціни», нет такого ID, нет веса, меньше 2 сортов или нет цены. Меню «✅ Перевірити ціни»
  показывает ошибки и считает выгоду каждого набора. После правок: «🚀 Оновити сайт».
  Резервные наборы можно задать и в catalog.json, раздел "sets" (если листа «Набори» нет).
  ВИД КАТАЛОГА (телефон). Над списком сортов — переключатель «Великі / Сітка»: по умолчанию
  крупные карточки, «Сітка» — 2 в ряд (компактнее, быстрее листать). Выбор запоминается в
  браузере клиента. На компьютере переключателя нет.

10. ДЕПЛОЙ: GITHUB ACTIONS (.github/workflows/build.yml)
----------------------------------------------------------------------
Название: «Build and Deploy Site». Запускается:
  • при каждом push в main;
  • вручную (workflow_dispatch) — это же вызывает кнопка «Оновити сайт»;
  • раз в час (cron '17 * * * *') — подтягивает правки из Таблицы.
Шаги: checkout → Python 3.12 → python tools/build.py → configure-pages →
upload-pages-artifact (вся папка) → deploy-pages.
Права: contents read, pages write, id-token write. Concurrency group
"pages" (запуски не идут одновременно).
В настройках репозитория: Settings → Pages → Source = GitHub Actions;
Custom domain = zrncoffee.com.ua (рекомендуется Enforce HTTPS). В
репозитории есть файл CNAME. DNS-записи домена у регистратора должны
указывать на GitHub Pages (где именно куплен домен — в этом документе не
зафиксировано; уточните у владельца).
Статус сборки: вкладка Actions репозитория (зелёная галочка / красный
крестик; в красном запуске есть текст причины на украинском).
Ограничение GitHub: если в репозитории 60 дней нет активности,
запланированные (cron) запуски приостанавливаются — кнопка «Оновити сайт»
и обычные push продолжают работать; для возобновления cron сделайте
любой commit или включите workflow заново на вкладке Actions.

14а. КЛУБ ZRN (ПОДПИСКА НА КОФЕ) — ПОЛНОЕ ОПИСАНИЕ
----------------------------------------------------------------------
Идея: подписка БЕЗ скидок (маржа 200 г ≈ 140 ₴, доставка ≈ 100 ₴). Цена
= цена каталога за 100 г × вес. Ценность — удобство, статусы, свобода.

Что видит клиент
 • Блок #club на главной (после «Бленди», пункт «Клуб» в меню): 4 шага
   Тип → Формат → Рівень/Сорт → Періодичність, живой расчёт цены, текст
   про оплату, форма заявки (модалка #clubOverlay). Код в index.html:
   CSS «Клуб ZRN», секция #club, модалка #clubOverlay, JS «Клуб ZRN»
   (CLUB, clubRender, clubSubmit), тексты — ключи club.* в ZRN_I18N (uk/ru).
 • ЦЕН В ПОДПИСКЕ КЛИЕНТ НЕ ВИДИТ (решение владельца): ни расчёта, ни цены за
   100 г, ни порога бесплатной доставки. My Choice — «цена как на сайте»,
   Roaster’s Choice — «цену согласуем перед каждой обжаркой». На сайт
   уходит только орієнтир для вас (My Choice: цена сорта за 100 г × вес,
   округлено до 5 ₴; для Roaster’s Choice — пусто) — он попадает в колонку
   «Сума» листа «Підписки» и вы можете его исправить.
 • В форме заявки клиент выбирает режим общения: Звичайний / Хочу більше
   близькості / Хочу менше повідомлень (потом меняется на странице
   «Моя підписка»).
 • Как клиент меняет подписку: блок «Як змінити підписку» на главной,
   ссылка в каждом письме и на экране «Заявку прийнято». Посмотреть
   страницу глазами клиента без реальной подписки: /subscription/?demo
 • Типы: My Choice (сам выбирает сорт из каталога) и Roaster’s Choice
   (сорт выбирает обжарщик; уровни Comfort и Premium).
 • Форматы: Personal («200 / 250 г» — вес = малая пачка выбранного сорта, w1; для Roaster’s Choice — heroW), Home 500 г, Reserve 1000 г. Сервер принимает любой вес 50–5000 г (Personal ≤350 г, Home ≤700 г, иначе Reserve). Количество чашек не указываем намеренно. Частота: 10 дней,
   2 недели, месяц (ограничений по весу нет — доставку при сумме ниже порога
   платит клиент по тарифу перевозчика).
 • Цена клиенту не показывается (см. выше). Comfort/Premium ₴ за 100 г в
   «Налаштування» — ТОЛЬКО ваша подсказка: бот пишет в заказе «орієнтир N ₴»
   для Roaster’s Choice. Пусто = без подсказки.
 • Заявка ничего не оплачивает. Оплата: за 1–2 дня до обжарки приходит
   сообщение с суммой; клиент присылает скриншот оплаты или пишет, когда
   оплатит; после подтверждения оплаты обжариваем и отправляем. Для ПЕРВОЙ
   поставки по желанию — наложенный платёж.
 • Страница «Моя підписка» (/subscription/, /ru/subscription/): вход по
   номеру SUB-NNNN + последние 4 цифры телефона (5 неудач → блок 15 мин).
   Действия: пропустить следующую отправку, пауза (до даты), возобновить,
   сменить сорт (My Choice), сменить отделение/адрес/перевозчика (обновляет
   и текущий заказ, если он ещё не отправлен), режим общения (Звичайна / Більше близькості /
   Менше повідомлень), особый запрос, отмена (двойное подтверждение).
   За {lead} (по умолчанию 3) дня до обжарки изменения блокируются
   (клиент видит, что нужно написать вам). Код — build.py: SB, SUB_HTML,
   Site.subscription_pages().
 • Перки (тексты): экономия времени, индивидуальное предложение, ранний
   доступ, статусы (6 мес. «Друг роастмастера», 1 год «Старий друг з
   особливими правами»), мини-сюрприз ~50 г раз в 3 месяца, «Живе слово»
   раз в квартал, кофейный паспорт (PDF — пока ведётся история в листе,
   сам PDF не автоматизирован), право на близость/тишину, свобода до
   последнего.

Что происходит в Google Таблице (order-sheet.gs, блок «ПІДПИСКИ»)
 • Листы: «Підписки» (одна строка = один подписчик, 34 колонки; статусы
   Нова заявка / Активна / Пауза / Скасована) и «Відправки підписок»

   – за {lead} дня до даты создаёт обычный заказ в «Замовлення» (метка,
